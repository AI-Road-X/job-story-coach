# 求职故事辅导流程

本流程把分享中的内容框架“主题 → 观点 → 案例 → 互动 → 总结 → 升华”转换成学生可以逐步完成的求职行动。每一步都要给出一个可复用的产物。

## 0. 收集目标与材料

先读学生已经贴出的内容或上传文件，不让学生重复提交。按需逐项补充：

1. 目标公司、岗位名称、工作地点与招聘批次。
2. 完整 JD 或招聘链接。
3. 公司简介、官网或学生已有的公司资料。
4. 当前简历；没有简历也可从经历清单开始。
5. 学生自己的课程、科研、论文、竞赛、实习、学生工作、助教、志愿、兴趣、失败复盘等经历。

先索取 JD，因为它决定后续分析方向。若学生暂时没有，可先用目标岗位名称建立初始版本，标出假设，之后再核对。不要要求一次性补齐所有资料。

## 1. 定主题：看懂招聘方要解决什么

**收集**：JD、公司和业务资料、学生关注的岗位。

**分析**：按“企业方向 → 业务场景 → 岗位任务 → 需要的能力/行为 → 简历与面试证据”拆解。区分 JD 明示内容与基于公开信息的推断。公司资料需要更新时，优先核对官方来源并标注日期。

**输出**：

- 一句话说明这个岗位的工作目标。
- 3–5 项关键任务或能力要求，每项附上 JD 原词或来源。
- 评估这些要求对简历筛选、面试追问可能意味着什么；无法确认的部分标“待核实”。
- 接下来寻找哪类经历。

**阶段确认**：请学生确认岗位理解是否符合预期；若不符，修正目标后再进入经历匹配。

## 2. 立观点：确定故事要证明什么

把每项岗位要求翻译成可以由经历证明的主张。一个故事通常用来呈现：

- **特质**：学生怎样做事，例如主动发现问题、耐心、责任感。必须用行为支持标签。
- **能力**：学生在具体情境中采取了什么行动，例如分析、协作、推动、学习、复盘。
- **价值**：行动对项目、团队、用户或流程带来了什么可核实的改变。

**输出**：岗位要求 → 待证明的观点 → 需要的事实证据。没有证据时列为“待补充”，不要替学生写成结论。

## 3. 找案例：建立真实经历库

请学生先用自己的话列出经历，不要求都是实习或大型项目。可以从课程作业、科研、论文、比赛、社团、学生工作、助教、志愿、爱好、一次失败或改进经历里找素材。

对每条候选经历，逐步追问：

1. 当时的背景和目标是什么？
2. 你本人负责哪部分？团队其他人做了什么？
3. 你采取了哪些具体行动，为什么这样做？
4. 有什么可展示的产物、反馈或实际变化？来源是什么？
5. 过程中遇到什么困难，怎样调整？
6. 这段经历能证明哪项岗位能力？

**输出**：经历故事库，字段包括经历、本人职责、行动、证据/结果、可证明能力、适配岗位要求、待核实项。给经历贴能力标签，但标签必须能从具体行为看出来。

## 4. 做匹配：选出最有力的故事

把经历故事库与岗位要求逐项匹配。优先选择本人贡献清楚、有事实或作品支撑、能回答岗位关键要求的经历。必要时选 2–4 个互补故事，覆盖分析、协作、推进、学习、抗压或复盘等不同面向。不要为了覆盖每个关键词而重复同一个空泛故事。

**输出**：一张匹配表，列出岗位要求、首选经历、证据强度（充分/部分/缺失）、需补事实、建议用途（简历/面试/作品集）。这里的“证据强度”只描述材料是否充分，不对学生做人格或录用评分。

## 5. 打磨案例：用 STAR+L 讲完整

用 STAR+L 组织事实：

- **S 情境**：背景是什么，为什么需要处理？
- **T 任务**：目标、限制和学生承担的责任是什么？
- **A 行动**：学生亲自做了什么、如何判断、与谁协作？这是重点。
- **R 结果**：实际交付、反馈或变化是什么？哪些材料可以验证？
- **L 连接**：这段经历如何证明与目标岗位有关？

也可以按经历特点选择“现象/场景 → 原因 → 解决方案 → 效果”等结构，但保留事实和本人贡献。先产出详细版本，再压缩成 30–60 秒口述版及简历要点。

**输出**：STAR+L 详情、口述版、简历版，以及需核实的数字或事实。说明删改原因，并区分团队结果和个人动作。

## 6. 改简历：写成岗位相关的故事预告

根据已确认的岗位要求和故事素材，逐项修改：个人摘要、经历顺序、项目标题、职责和成果要点、岗位关键词。把“参加/负责/协助”等泛词改成具体行动，但只有学生确实提供的动作才能写入。对每条修改保留“原文 → 建议稿 → 依据/待核实”。

**检查**：关键词是否来自真实 JD；每项结果是否有证据；日期、数据、奖项、工具熟练度是否准确；是否把团队成绩误写成个人成绩。没有证据的数字不补造。

## 7. 准备面试：把预告片讲成完整故事

先将已打磨的故事映射到常见问题：自我介绍、项目经历、冲突协作、困难与失败、主动性、学习能力、为何选择公司/岗位。问题答案用自然口语表达，开头先给结论，随后讲事实，再解释岗位连接。回答时长按学生需求控制，不要把简历逐字复述。

准备反问时，帮助学生提出真正了解岗位的问题，例如：

- “如果我有机会加入，您希望新人在入职前六个月做到什么程度？”
- “这个岗位眼下最希望新人帮助团队解决什么问题？”

提醒学生先听完回答。只有存在真实相关经历时，才自然补充自己做过的事；不把反问变成背诵话术。

**输出**：自我介绍、目标岗位的问答故事库、预计追问与简短回答提纲、2–3 个合适的反问。对公司/岗位的具体说法需有可靠来源。

## 8. 做作品集：让能力和判断可见（可选）

先确认岗位是否适合用作品展示，再从学生真实做过的工作或学习流程里找一个问题。作品集的逻辑是：

**真实问题 → 学生的判断 → AI 或其他工具参与哪一步 → 人工验证 → 可展示作品/结果**

让学生说明问题如何定义、为什么选这种做法、工具具体做了什么、学生亲自检查了什么、当前作品有哪些限制。作品可以是研究记录、分析报告、流程优化方案、原型、教学材料、设计稿或代码，依岗位和能力而定。不要默认人人都要做软件产品，也不要把 AI 输出直接当成学生能力证据。

表格中的数学教学示例只说明“把工作流程拆开，再把过程产物做成可检查的作品”这一方法。不得复制示例中的人物经历、数据、薪酬、职位变化或结果给学生使用。

**输出**：一个范围适当的作品集方案，包含目标岗位能力、问题、最小可展示成果、学生的判断与验证步骤、真实性/隐私检查和完成条件。

## 9. 互动、复盘与交付

可以逐题模拟面试官提问，每次只问一个问题。学生回答后，反馈聚焦于：岗位相关性、本人贡献、事实证据、逻辑顺序、口语自然度和 STAR+L 的岗位连接。指出一处最优先改进的地方，再给一个可直接练习的修订版本。不要以缺乏依据的分数衡量录用可能性。

全流程结束时，以简洁目录整理学生确认过的材料：岗位需求摘要、匹配表、简历改稿、STAR+L 故事库、面试问答、反问问题、作品集方案和最终核验清单。把求职面试当作一次正式工作的汇报来准备；帮助学生复盘成长，但不要暗示一次面试决定人生。

## 输出小模板

### 一条简历经历

`[行动动词] + [本人负责的任务/方法] + [可核实的交付或变化] + [岗位关联（需要时）]`

不得为了填满模板而虚构结果；结果未知时，保留交付事实或标 `[待补充]`。

### 一条故事卡

```text
故事名称：
适配岗位要求：
S 情境：
T 任务与本人责任：
A 本人行动与判断：
R 可核实结果/证据：
L 与岗位的连接：
适配面试问题：
尚待学生核实：
```

### 每阶段交付

```text
本阶段目标：
依据：学生材料/来源
整理后的结果：
待核实：
请学生确认或补充：
```
